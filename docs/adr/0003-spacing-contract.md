# ADR 0003 · 간격 계약

## 상태

채택 (2026-10-20, 4차 고도화)

## 맥락

AI가 화면을 만들 때 가장 자주 틀리는 것이 간격이다. 부품마다 제목→본문 거리가 다르고(4·6·12·16·24px), 라벨과 값이 멀고, 상자 안의 글자가 가장자리에 붙고, 6·10·14px 같은 격자 밖 값이 섞이고, 색을 입힌 섹션 안에 색을 입힌 섹션을 넣어 안쪽 여백이 두 배가 된다. 3차까지는 이런 값이 CSS 곳곳에 손으로 적혀 있었다(실측: 격자 밖 margin·padding·gap 13,654곳, 제목→본문 간격이 부품마다 달라 244건, 근접 위반 233건).

사용자는 Blueprint에 간격 값을 쓰지 못한다. 따라서 실수는 사용자 입력이 아니라 "기본 재료"(토큰·부품 CSS·조립 규칙)에서 생긴다.

## 결정

1. 간격은 밀도 축이 고르는 토큰 한 벌(`src/spacing.mjs` `SPACE`)이다. 순서(tight < near ≤ item ≤ head < gap < section < band)가 뒤집히면 시험이 실패한다.
2. CSS는 그 토큰이나 4px 격자 값(및 1·2px 헤어라인)만 쓸 수 있다. `lintSpacing`이 모든 스타일 소스를 훑고, 격자 밖 값·임의 배수·허용되지 않은 `clamp()`는 시험에서 실패한다.
3. 부품 제목→본문, 라벨→값 같은 부품을 가로지르는 관계는 부품 CSS에 흩어 두지 않고 `contractCSS`가 한 번 생성한다.
4. 안쪽 여백이 겹치는 구성(색 섹션 중첩, 섹션 3단 중첩)은 검증기가 거부한다(`SURFACE_NEST`, `SECTION_DEPTH`, 규칙 R20).
5. 실제 화면에서의 어긋남은 `scripts/design-qa/spacing-probe.mjs`가 실측한다(HEAD_GAP, PAIR_GAP, PROXIMITY, EDGE, PAD_ASYM, CTRL_PAD, OFF_SCALE, HEAD_ORPHAN). 템플릿 61개 × 밀도 3종 × 폭 2종을 `e2e/spacing.spec.mjs`가 돌리고, 일부러 틀린 페이지로 각 점검이 실제로 걸리는지(음성 대조)도 확인한다.
6. 규칙 문서(`docs/spacing.md`)는 같은 데이터에서 생성한다. 손으로 고치지 않는다.

## 근거

- winterholic-base `03-spacing-layout.md`: 4px 격자, "가까운 것은 가깝게", "안쪽 패딩 ≤ 바깥 간격", 값은 `space.*` 중 하나. 이 ADR은 같은 원칙을 코드로 강제한다. 차이는 문서 "하지 말 것"의 "자식에 margin-bottom을 주지 않는다"를 따르지 않고 제목→본문에 margin을 쓴다는 점이다(생성 계약 층 한 곳에 모아 두었다).
- frontend-design `spacing-layout.md` §3: 관계 거리 = 의미 거리.

## 결과와 한계

- 격자 밖 값 13,654 → 0, 실측 위반 0(템플릿 61 × 밀도 3 × 폭 2).
- 보증하는 것은 간격의 일관성이다. 보기 좋은지는 보증하지 않는다.
- 실측은 템플릿 표본이다. test-lab 3,380건 전수에는 CSS 린트와 가로 넘침만 돌린다.
- 근접(S03) 실측은 표면이 없는 묶음끼리만 비교한다.
- 카드 제목↔본문은 near(8px)다. winterholic-base는 12px(`space.3`)를 쓰므로 한 단계 더 붙였다.

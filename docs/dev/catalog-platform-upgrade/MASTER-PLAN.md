## 1. 프로젝트 비전 및 최종 목적

Static Kit은 프롬프트 기반의 단순 HTML 생성기나 디자인 예제 전시장이 아니다.
**디자인에 필요한 모든 재료를 충분히 사전 정의하고, 코드 기반의 결정론적 선택·검증·조립을 통해 다양한 고품질 UI를 만들어내는 범용 디자인 조립 플랫폼이다.**

현재 코어 엔진(ADR 0012)의 조립 파이프라인과 엄격한 검증 체계는 구축되었으나, 실제 사용할 수 있는 디자인 재료의 다양성 부족, 카탈로그 웹사이트의 iframe 기반 성능 저하, 구형-신규 시스템 간 사용자 경험의 분절이 남아 있다.
본 고도화 프로젝트는 프론트엔드 성능 병목을 우선 해소한 후, 색상·타이포·컴포넌트·시각 패밀리를 대규모로 확충하여 제품 수준의 조립 플랫폼으로 완성한다.

## 2. 병렬 작업 트랙 체계 (Track A ~ Track G)

작업량이 방대하므로 7개 전문 트랙으로 분할하여 병렬 추진한다. 각 트랙은 `CONTRACTS.md`의 파일 소유권 규칙을 엄격히 준수한다.

    │              │              │              │              │

### Track A: 성능 및 플랫폼 기반 (Performance & Engine)
- **주요 목표**: iframe 제거, 사전 생성 파이프라인 구축, 결정론적 캐싱, 번들 최적화.
- **핵심 산출물**: 대표 미리보기 사전 생성 스크립트, LRU 메모리 캐시, 경량 카탈로그 인덱스.
- **성능 목표**: LCP 2.5s 이하, INP 200ms 이하, 일반 카탈로그 목록 iframe 0개, 일반 목록 요청 시 동적 컴파일 0회.

### Track B: 색상 체계 (Color System)
- **주요 목표**: 팔레트 200종 확충, 서브토큰 세트 25종 확충, 토큰 계층(Primitive/Semantic/State/Component/Chart) 완성.
- **핵심 산출물**: `src/platform/data/palettes.mjs`, `src/platform/data/subtoken-sets.mjs`, 통합 색상 작업대.
- **권리 원칙**: Coolors 427 팔레트 공개 카탈로그 노출 차단, 자체 원색 시드 라이브러리 구축.

### Track C: 타이포그래피 (Typography)
- **주요 목표**: 독립 타이포 시스템 40종 확충(10개 계열 × 4종), 역할 27종(REQUEST §5.3) 스케일 정립, 다국어 및 한글 한도 관리.
- **핵심 산출물**: `src/platform/data/type-systems.mjs`, 타이포그래피 전면 개편(전체 카드 탐색, Specimen, 4분할 비교기).

### Track D: 컴포넌트 재료 (Component Materials)
- **주요 목표**: 필수 컴포넌트 인벤토리(A~O 207개 항목, REQUEST §6.2 실측. `Bottom Navigation`이 E·O에 겹쳐 고유 이름은 206개) 전수 지원 경로 확보, 목적별 및 복합 컴포넌트 120종 이상 실질 구현.
- **핵심 산출물**: `src/materials/` 신규 컨트롤 계약, `src/platform/families/` 목적 패밀리, 상태 전이 및 접근성 계약.

### Track E: 시각 패밀리 및 Foundations (Visual Families & Foundations)
- **주요 목표**: 시각 패밀리 12종(기존 4종 확장), 차트 29유형, 레이아웃 24종, 표면/모션/배경 재료 확충.
- **핵심 산출물**: `src/platform/data/families.mjs`, `src/platform/data/charts.mjs`, Foundations 전시장 페이지 개편.

### Track F: 웹 제품 경험 (Web Experience)
- **주요 목표**: 카탈로그 탐색 경험 전면 개편, 카테고리 탭 도입, 컴포넌트 상세 9개 탭 완결, Studio 조립 연결.
- **핵심 산출물**: `apps/web/app/components/`, `apps/web/app/studio/`, `apps/web/app/explore/` UI 개편.

### Track G: 통합 및 품질 거버넌스 (Integration & Quality)
- **주요 목표**: Material Coverage Manifest 실시간 동기화, 실제 출력 차이 검사, 브라우저 E2E, Vercel 배포 검증.
- **핵심 산출물**: `scripts/generate-material-coverage.mjs`, `TASK-LEDGER.json`, 회귀 방지 품질 게이트.

## 4. 최종 완료 판정 기준 (§16 대조표)

- [ ] 공개 및 조립 가능한 자체 팔레트 200개 이상 확보
- [ ] 실질적으로 차별화된 서브토큰 세트 25개 이상 확보

- [ ] §6.2 전체 컴포넌트 인벤토리(A~O 207개 항목) 지원 경로 확인

# 레이아웃 원시 요소 (Layout Primitives)

> 이 문서는 `src/layout.mjs`에서 생성됩니다(`npm run docs`). 손으로 고치지 않습니다.

부품은 자기 열 수와 너비를 정하지 않는다. 부품은 **원시 요소**(아래 표) 중 하나를 고르고, 값은 토큰과 컨테이너가 정한다.

| 원시 요소 | 하는 일 | 쓰는 곳 |
|---|---|---|
| 쌓기(stack) | 세로로 쌓는 묶음. 간격은 spacing 역할(tight·near·item·head·gap)로만 정한다. | .kit-section-inner, .kit-form, .kit-card-body … |
| 나열(cluster) | 가로로 나열하고 넘치면 줄바꿈하는 묶음(버튼 줄, 칩, 태그). | .kit-actions, .kit-tags … |
| 격자 흐름(flow) | 같은 크기 항목의 격자. 열 수는 컨테이너 폭과 항목 수가 정한다(마지막 줄에 한 칸만 남기지 않는다). | [data-flow] (이 파일이 생성) |
| 컨테이너(container) | 콘텐츠 폭(--kit-max)과 좌우 여백(--kit-gutter)을 정한다. 읽기 폭은 측정 역할로만 제한한다. | .kit-main, [data-measure] |
| 2분할(split) | 글과 시각 요소를 나란히. 좁은 폭에서는 한 열로 접힌다. | .kit-split, .kit-aside |
| 벤토(bento) | 크기가 다른 칸의 격자. 칸의 크기는 내용이 정한다(시각 요소가 있는 칸만 2×2). | .kit-bento |

## 격자 흐름: 마지막 줄에 한 칸만 남기지 않는다

실측(6차 진단)에서 조합의 28.5%가 같은 크기 카드의 마지막 줄에 한 칸만 남았다. 원인은 열 수를 부품이 고정하고(`two`·`three`) 뷰포트 미디어 쿼리로만 줄였기 때문이다. 사이드바나 2분할 안에서는 뷰포트가 넓어도 칸은 좁다.

규칙:

1. 열 수의 상한은 컨테이너 폭이 정한다: 0px~ 1열, 504px~ 2열, 768px~ 3열, 1032px~ 4열(칸 240px 이상).
2. 그 안에서 열 수는 항목 수가 정한다. 마지막 줄이 가득 차면 0점, 한 칸만 남으면 100점, 그 밖에는 1점이며 열이 많을수록 조금 낫다(`bestCols`).
3. 지표·미디어 카드처럼 작게 접어도 읽히는 항목(`data-dense`)은 가장 좁은 폭에서 2열을 허용한다.
4. 항목이 12개를 넘는 흐름은 이 규칙의 대상이 아니다.

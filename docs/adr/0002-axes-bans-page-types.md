# ADR 0002 · 축·금지 조합·페이지 유형으로 카탈로그를 확장한다

- 상태: 채택 · 2026-10-18
- 배경: 카탈로그 1.0(테마 6, 셸 4, 부품 13)은 "너무 부실하다"는 피드백을 받았다. 동료 저장소는 시스템 38종·레이아웃 38종·콘텐츠 구조 9종·아이콘 48개를 갖는다. 격차 분석은 `docs/gap-analysis.md`.
- 제약: 코드 강제 철학 유지(카탈로그 밖 값 생성 불가), 동료 AGPL 코드 복사 금지, Coolors 팔레트는 테마당 여러 개, 모든 팔레트×역할 대비 검사.

## 결정

1. **테마는 "값의 묶음"이다.** 테마 = 분류 + 설명 + 기본 축 프로필 + 금지 값 + 팔레트 후보. 새 테마를 만드는 비용은 데이터 한 줄이고, 시각 구현은 축이 담당한다. 동료 시스템 38종은 테마의 `covers`로 대응시키고 값은 환산 표로만 남긴다.
2. **스타일은 축으로 분해한다.** 15축(모드·셸·서체·밀도·모서리·컨트롤·깊이·모션·아이콘·장식·배경·폭·스케일·굵기·푸터). 카드 모서리와 버튼 모양을 분리해 "직각 카드+알약 버튼"을 표현한다. 축의 모든 값은 구현표가 있어야 하고 테스트가 enum과 구현표의 일치를 검사한다.
3. **금지 조합은 데이터다.** 각 금지는 `id, uses, bad(), why, source, fix`를 가진다. `uses`는 술어가 읽는 축 목록이며 감사가 Proxy로 증명한다. 그래서 허용 공간을 `uses`로 연결되는 묶음별로 나누어 정확히 센다. `fix`는 작성기와 합성기가 쓰는 대안일 뿐이고 검증기는 고치지 않는다.
4. **페이지 유형이 구조를 강제한다.** 필수·금지·허용 부품, 최상위 노드 수, 셸·폭 제한, 상태 페이지의 두 번째 노드. "랜딩에는 칸반이 없다", "인증 화면은 폼 하나와 보조 안내뿐" 같은 판단을 코드로 둔다.
5. **부품은 55종으로 늘리되 폐쇄형을 유지한다.** 모든 부품은 카탈로그의 한 항목(필드·선택 필드·자식·예시)이고, 예시는 감사에서 실제 컴파일된다. 차트는 SVG를 데이터에서 만들고 텍스트 대안과 표를 낸다. 인터랙션은 고정 런타임(폼 확인·탭·칩·드롭다운)으로 제한한다.
6. **다크 대응은 auto까지.** auto는 두 토큰 세트를 모두 검증한다. 반전 구역은 반대 모드의 검증된 세트를 쓰므로 별도 반전 토큰과 별도 검사가 필요 없다.
7. **CSS는 사용한 부품만.** 스타일시트는 토큰·축 변수·셸·사용 부품 조각으로 조립해 산출물이 작고 예시마다 다르다.
8. **갤러리는 같은 컴파일러를 쓴다.** 의존성 없는 작은 번들러가 소스를 IIFE로 묶어 단일 HTML에 넣는다. 테스트가 번들 출력과 Node 출력의 바이트 일치를 검사한다.
9. **호환성.** Blueprint 2.0·카탈로그 2.0.0이 아니면 거부한다. 1.x는 `kit migrate`로 새 필수 필드(`pageType: general`, 테마 기본 축)만 더해 변환하고, 그 외는 건드리지 않는다.

## 대안과 판단

| 대안 | 판단 |
|---|---|
| 동료 방식(시스템 38종을 토큰 묶음으로 복제) | 라이선스와 브랜드 문제, 코드 강제 철학과 무관한 데이터 복제. 성격만 환산해 대응 |
| 테마마다 CSS 작성 | 40×N CSS는 검증 불가. 축 조합으로 표현 |
| 금지 조합을 프롬프트·문서로 안내 | 철학 후퇴. 코드와 테스트로 둔다 |
| 허용 조합 전수 컴파일 | 약 1.6×10^11개로 불가. 쌍별 커버링+요인 분해 계수+핵심 전수(팔레트×모드, 템플릿×테마)로 대체 |

## 한계

- 조합의 시각 품질은 보증하지 않는다. 접근성·구조·일관성의 하한만 코드가 지킨다.
- 쌍별 커버링은 3개 이상 축의 상호작용 결함을 놓칠 수 있다. 핵심 3축(팔레트×모드×셸)은 전수한다.
- 페이지 유형의 필수·금지 목록은 설계 판단이며 반례가 나오면 카탈로그를 개정한다.

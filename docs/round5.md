# 5차 개선 기록 (2026-10-20)

사용자 평은 "UI 자체의 완성도가 너무 떨어진다"였다. 요청 여섯 가지를 하나씩 기록한다. 수치는 모두 이 저장소의 명령으로 다시 낼 수 있다.

## 1. 조합 폭 확대: 종류를 늘리고 선택지마다 변형을 둔다

이전에는 팔레트가 테마 하나에 묶여(`PALETTE_THEME`) 1:1 대응이었다. 지금은 템플릿·테마·팔레트가 독립이고, 각각 변형이 있다.

| 항목 | 4차 | 5차 |

| 템플릿 | 61 | **85** (+24: 기업용 솔루션·개발자 도구·청첩장·영업 대시보드·API 레퍼런스·뉴스 메인 등) |
| 템플릿 구성 변형 | 없음 | **슬롯 264곳, 선택지 405개** (히어로·기능 배열·카드 스타일·표·목록·구역 리듬·순서·좌우 배치·탭·단계·타임라인·갤러리·메뉴판) |

## 2. 색 토큰 다양화: 흔한 보라-파랑 대신 Coolors 인기 팔레트

- **조사.** 2026-10-20 호스트의 Chromium으로 coolors.co 인기 목록 73개 페이지를 스크롤하며 스워치·제목·**좋아요 수**를 읽었다(일반 fetch가 아니라 렌더 페이지). 중복과 파싱 오류(제목이 순번으로 읽힌 56개)를 걸러 1,288개를 `docs/evidence/coolors-popular-2026-10-20.json`에 남겼다. 가장 많이 좋아요를 받은 것은 Sunny Beach Day(12.4만), Olive Garden Feast(9.7만), Pastel Dreamland Adventure(8.8만)다.
- **선정.** `scripts/palette-pick.mjs`가 계열(11개)별 상한 안에서 좋아요 순으로 채운다. 보라-파랑이 대부분인 팔레트와 네온 무지개는 상한을 둬 퍼플 계열은 16개(3.7%), 어느 테마의 기본값도 퍼플이 아니다(허브·아틀리에·플레이풀·네온·키즈·컬러블록·녹턴·게임·웨딩은 예외로 허용). 이전 기본값에는 오로라(보라 `#613DC1`), 인사이트(분석 대시보드에 핫핑크), 러닝(`#F50062`) 같은 성격과 어긋난 것이 있어 사람이 화면으로 읽고 19개 테마의 기본값을 고쳤다.
- **대비.** 427개 × 라이트·다크 = 854모드, 89,670쌍 전부 WCAG AA 이상(본문 7:1·보조 4.5:1·구조선·포커스·차트 3:1). 선정이 아니라 토큰 해석이 보장하며 `scripts/audit.mjs`가 전수 확인한다.
- 기록: [팔레트 근거](palettes.md)(방법, 계열별 수, 좋아요 상위 24, 테마별 기본값).
- 한계: 인기는 좋아요 수일 뿐 품질의 증거가 아니다. Coolors 팔레트 이름·색의 재사용 조건은 **확인 필요**.

## 3. 조립 재료 품질: 계측으로 찾아 닫기

눈대중 대신 두 도구로 찾았다. 간격은 기존 `spacing-probe`, 글줄·넘침은 새 `scripts/design-qa/text-probe.mjs`(끝줄 고아·제목 고아·버튼 줄바꿈·좁은 칸·가로 넘침·잘림·값 줄바꿈·짧은 글줄). 부품 전수는 `scripts/design-qa/parts-sheet.mjs`로 변형별 렌더를 390·1280px로 찍어 눈으로도 봤다. 진단은 템플릿 85개 × 2~3테마 × 360·390·768·1280px(992쪽).

찾아서 고친 것:

| 결함 | 증상 | 원인과 처치 |
|---|---|---|
| 달력 | 390px에서 7열 중 4열만 보이고 잘림 | 560px 고정 최소 폭. 좁은 칸에서는 점으로 줄이고 아래에 일정 목록(`kit-cal-agenda`)을 낸다 |
| 단계 표시 | 360px에서 가로 17px 넘침 | 현재 단계만 라벨을 보이고 나머지는 번호만 |
| 히어로 제목 | 후원 캠페인에서 96px 글자가 "올해 목표,/나무/10,000그루." 3줄(한 단어 줄) | ch 폭이 한글에 절반이라 칸이 좁았다. 한글 가중치로 한 줄 글자 수 구간(`cplOf`)을 구해 칸 폭(cqw)에 맞춰 줄임 |
| 지표·가격 | "6,420그루"·"39,000원"이 숫자 중간에서 줄바꿈, 금액이 카드 가장자리에 10px로 붙음 | `overflow-wrap:anywhere`가 원인. 본문을 `break-word`로 바꾸고 값 폭 구간(`vlOf`)으로 칸에 맞춰 줄임 |
| 알림 배너 | 내용이 가운데로 쏠려 왼쪽이 비어 보임 | 정렬을 왼쪽으로, 토스트의 곡선 위 4px 테두리는 안쪽 그림자로 |
| 버튼 | 장바구니 담기·헤더 액션이 두 줄 | 헤더 액션 줄바꿈 금지, 구매 박스 버튼은 내용 폭 기준으로 줄 바꿈 |
| 네비 | 모바일에서 마지막 항목이 글자 중간에서 잘림 | 오른쪽 페이드로 잘린 항목이 있음을 알림 |
| 글줄 폭 제한 | h1·본문이 한글 13~25글자에서 일찍 줄바꿈 | ch(영문 "0" 폭) 제한 17곳을 한글 기준 em으로 교체 |

- 재발 방지: `e2e/text.spec.mjs`가 템플릿 85개 × 회전 테마 × 4폭에서 가로 넘침·잘림·버튼 줄바꿈·값 줄바꿈·좁은 칸·제목 고아가 하나도 없음을 확인하고, 깨진 샘플 페이지에서 각 결함 코드가 실제로 잡히는지(음성 대조)도 확인한다. 간격 실측(`e2e/spacing.spec.mjs`)은 85개 템플릿 × 밀도 3종으로 늘었고 지적 0건이다.
- 남은 지적(막지 않고 건수만 기록): 본문 끝줄이 짧은 경우 67곳(단어 단위 줄바꿈의 자연스러운 결과가 섞임, 표 셀·칸반 카드 제목 등), 짧은 글줄 폭 7곳.
- 못 본 것: 실제 Safari/iOS, 실기기 폰트. 헤드리스 Chromium(macOS 폰트)으로 측정했고 Linux CI에서 달라질 수 있어 push 후 CI로 확인한다.

## 4. 배포 사이트에서 비교 문서 제거

- `docs/gap-analysis.*`(동료 레포 대조)를 배포물과 조립기 내비에서 내리고 `docs/archive/gap-analysis.md`로만 보관한다(생성은 `scripts/docs.mjs`). 설계서에서 동료 레포·Katalog·"사용자 피드백" 문장을 뺐다. 공개 `catalog.json`에서도 동료 대조용 `covers` 필드를 뺐다.
- 내비는 조립기 · 카탈로그 · 샘플 갤러리 · 설계서 · 팔레트 근거 · 간격 규칙으로 정리했다. `e2e/workbench.spec.mjs`가 조립기에 비교 링크가 없음을 확인한다.

## 5. 결과물 새 창·전체 화면 모달, 잘림의 근본 수정

- 원인: 미리보기 iframe이 남는 가로 폭(750px 안팎)에 맞춰 렌더되어 데스크톱 화면이 좁은 태블릿 배치로 그려졌고, 3단 레이아웃에서 우측이 밀렸다.
- 처치: 결과물을 휴대폰 390·태블릿 768·데스크톱 1280 고정 폭으로 그린 뒤 가용 영역에 맞춰 축소(`src/workbench/viewport.mjs`, 순수 함수 시험 포함). 맞춤은 영역 폭 그대로. 새 창(blob 문서, `opener` 해제)과 `<dialog>` 전체 화면 모달(폭 전환·다크 전환·새 창·Esc)을 제공한다.
- 증거: `e2e/workbench.spec.mjs`의 "preview is never clipped"(5개 뷰포트 × 4개 폭에서 셸이 무대 안에 있고 문서가 넘치지 않음), "full-screen modal and new window".

## 6. 조립기 UI 재설계

- 상단: 큰 소개 영역을 걷어 내고 56px 앱 바 + 현재 조합 요약 + 내보내기. 작업대는 화면 높이에 고정된 3단(선택·미리보기·구조), 각 패널은 자체 스크롤. 1560px 이상에서는 구조 패널이 열이 되고, 그보다 좁으면 서랍으로 열린다. 1024px 미만은 선택·미리보기·구조 탭.
- 선택 패널: 페이지(템플릿·구성 변형) → 시각 언어(테마·테마 변형) → 색(모드 분절 컨트롤, 팔레트 계열 필터·검색·좋아요 표시) → 구조와 리듬(배치·글자·모양·분위기 네 묶음).
- 규칙은 막는 대신 안내한다: 테마·페이지 유형이 막은 값은 비활성+이유, 다른 축과 부딪히는 값은 고르면 규칙의 대안으로 부딪힌 축을 함께 바꾸고 알려 준다(`src/workbench/axes.mjs`).
- 카탈로그 탭: 템플릿 85·테마 54·팔레트 427·부품 55의 실제 렌더 썸네일(보일 때만 컴파일)과 "이 템플릿/테마 변형/색으로 조립".
- 접근성: 라디오·분절 컨트롤·다이얼로그를 네이티브 요소로, 포커스 복귀, 44px 대신 36~40px 컨트롤(촘촘한 작업 도구 영역, WCAG 2.5.8 24px 이상).

## 미검증·한계

- Safari/iOS, 스크린리더, 실기기에서의 새 창·모달·스케일 동작은 확인하지 못했다(Chromium 에뮬레이션만).
- 템플릿 24개와 구성 변형 405개의 내용·미감은 사람이 전수로 보지 않았다. 검증·컴파일·실측·대표 화면만 확인했다.
- 팔레트 선정은 취향의 근사이며 미감 보증이 아니다. 계열 분류는 브랜드 스워치 기준이라 사람이 보는 이름과 다를 수 있다(예: 빨강 포인트의 청색 팔레트가 레드 계열).

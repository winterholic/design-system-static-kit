1. 한 줄 요약

이 저장소는 사전에 정의한 카탈로그 안의 선택만 JSON 트리로 조립해 HTML/CSS를 만드는 컴파일러입니다. 규칙은 프롬프트가 아니라 코드가 강제합니다. 카탈로그에 없는 값, 허용되지 않은 조합, 대비가 모자라는 색, 손으로 고친 산출물은 생성되거나 통과하지 못합니다.

카탈로그 2.0.0은 테마 40종, Coolors 팔레트 160개, 셸 10종, 부품 55종, 페이지 유형 16종, 템플릿 61종, 아이콘 87개, 스타일 축 15개입니다. 카카오 Katalog의 원 발표는 특정하지 못했으며(확인 필요) 이 구조는 "가능한 경우의 수를 미리 정의하고 트리로 조립한다"는 취지를 독립적으로 구현한 것입니다.

2. 파이프라인과 강제 경계

Blueprint(JSON) → 검증기(스키마·간선·조합·페이지 유형·링크·데이터)
               → 토큰 해석(팔레트×모드, 대비 게이트)
               → 렌더(부품 → HTML) + 스타일(축 → CSS, 사용 부품만)
               → 산출물 5파일 + SHA-256 해시 → check로 재현 검사
  • 입력 경계. 알 수 없는 속성은 모두 UNKNOWN_KEY입니다. 문자열은 항상 이스케이프되고, 링크는 HTTPS·#main·페이지에 선언된 앵커만 허용합니다. 생성 페이지의 스크립트는 고정 런타임(폼 확인, 탭, 필터 칩, 드롭다운) 하나뿐이고 CSP로 네트워크를 막습니다.
  • 한계. 카탈로그와 검사기 자체를 고칠 권한은 막지 못합니다. 새 표현이 필요하면 근거와 반례를 남겨 카탈로그를 개정합니다. 사용자 승인이나 미감을 보증하는 기록은 만들지 않습니다.
  • 버전. Blueprint 2.0과 카탈로그 2.0.0이 아니면 거부합니다. 1.x 입력은 kit migrate로 변환합니다.

5. 토큰과 대비

팔레트의 원본 색은 보존하고, 역할별 토큰을 팔레트×모드마다 계산합니다. 역할은 canvas surface soft sunken accentSoft text muted action link focus rule border success warning danger info accent accentInk chart1~5입니다. 기준을 넘지 못하면 원색을 검정(라이트) 또는 흰색(다크) 쪽으로 최소한만 이동합니다.

11. 산출물과 사용

  • 작성기(index.html): 템플릿·테마·팔레트·모드·13개 축을 고르고 트리를 편집합니다. 금지 조합은 규칙과 대안을 보이며 자동 수정할 수 있습니다.
  • 갤러리(site/gallery/index.html): 컴파일러를 포함한 단일 파일. 휴대폰에서 템플릿·테마·부품·축을 열어 보고 저장합니다.
  • CLI: catalog | templates | themes | init | migrate | validate | build | check.
  • 예시: site/examples/<template>/ 61개, site/examples/themes/<theme>/ 40개.
  • 카탈로그 API: site/v1/catalog.json, site/v1/blueprint.schema.json.

12. 출처와 라이선스

  • 동료분 레포 yehsb123/design-system-kit: AGPL-3.0. 축과 수량만 대조했고 코드는 복사하지 않았습니다.
  • 토큰·타이포·간격·상태 철학: winterholic-design-system의 winterholic-base 문서(04 모양·깊이, 05 모션, 07 상태, 08 접근성, 09 다크, 12 페이지 패턴)와 로컬 frontend-design 스킬.
  • 팔레트: Coolors 렌더 페이지를 2026-10-18에 관측한 목록(docs/evidence/coolors-palettes.json). 각 팔레트에 원본 URL을 보존했습니다.
  • 접근성 기준: WCAG 2.2 SC 1.4.3, 1.4.11, 2.5.8, 1.1.1, 2.4.4.
  • 카카오 Katalog: 원 발표 확인 필요. 이 문서는 해당 발표의 구현·효과를 인용하지 않습니다.

13. 범위 밖과 알려진 한계

  • 상태가 있는 위젯(모달, 토스트의 자동 소멸)과 실제 지도·결제·인증 동작은 정적 코드 범위 밖입니다.
  • 실제 Safari/iOS, 스크린리더, 고대비 모드의 실기기 검증은 하지 않았습니다(Chromium 에뮬레이션만).
  • Coolors 이름·팔레트의 재사용 조건은 확인하지 않았습니다. 각 팔레트의 원본 URL을 남겼습니다.
  • 정확한 미감은 보증하지 않습니다. 규칙은 접근성·일관성·구조의 하한을 지킬 뿐입니다.
  • 서체는 시스템 폰트 스택입니다. 웹폰트를 싣지 않는 이유(CSP와 외부 요청 금지)와 결과는 docs/foundation.md에 있습니다.

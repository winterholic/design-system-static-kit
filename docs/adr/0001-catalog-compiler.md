# ADR 0001 · 카탈로그를 실행 규약으로 만든다

- 상태: 채택 · 2026-10-18
- 목표: 에이전트가 미감을 추측해 CSS를 쓰는 범위를 줄이고, 미리 검토한 선택을 재현 가능한 코드로 조립한다.
- 독자: 시스템 소유자·소비 프로젝트 개발자·에이전트.

## 비교와 결정

| 선택 | 장점 | 한계 | 판정 |
|---|---|---|---|
| 프롬프트 조립 | 프레임워크 자유, 빠른 도입 | 지침 미준수·임의값을 빌드에서 거부하지 못함 | 철학만 참고 |
| React prop 제약 | 앱 통합에 유리 | arbitrary children/style 우회, 런타임 의존 | 향후 어댑터 |
| 폐쇄형 JSON 트리 → 검증 → 정적 HTML/CSS | 입력 경계와 출력이 작고 검증 가능, 서버·AI 없이 재현 | 새 부품은 시스템 개정 필요 | 채택 |

## 계약

`theme → palette candidate`를 고르고 `shell × typography × density × radius`를 독립 선택한다. 조립 트리는 `page → section/grid → leaf`라는 허용 간선만 통과한다. node 종류·속성·variant·자식 수·깊이·문자 길이를 검증한다. 알 수 없는 키는 오류다. `style`, `className`, `html`, 스크립트, 임의 토큰 값은 입력 언어에 없다. 텍스트는 HTML escape, 링크는 HTTPS 또는 정의된 문서 앵커만 허용한다.

카탈로그는 색상 후보를 여러 개 갖는다. 원색은 원본으로 보존하고 의미 토큰은 라이트/다크 각각 대비를 보정한다. 실제 본문·보조본문·링크·버튼·상태·포커스/구조선 쌍을 검사한다. 보정값과 원값을 함께 기록한다. 좋은 디자인의 수학적 보증을 주장하지 않는다. 위계·근접성·상태·접근성의 검토된 범위를 코드화한다.

## 강제 경계

컴파일러 API·CLI·웹 UI는 같은 validator/compiler를 쓴다. 생성 산출물은 입력과 카탈로그 버전을 manifest에 기록한다. `kit check`는 재컴파일 결과와 HTML/CSS/토큰/manifest를 바이트 단위로 비교해 수동 수정·추가 파일·누락을 거부한다. CI는 모든 예제를 재빌드하고 버전 관리된 산출물과 비교한다.

저장소 쓰기 권한 보유자가 컴파일러·검사기·CI를 같이 바꿀 수 있는 것까지 암호학적으로 막지는 않는다. 소비 프로젝트는 생성 디렉터리를 그대로 사용하고, CI 필수 검사/보호 브랜치·CODEOWNERS를 조직 정책으로 설정해야 한다. 이 저장소는 GitHub 보호 정책을 임의로 활성화하지 않는다.

## 잘못된 규칙의 수정

규칙에는 ID·의도·출처·반례 fixture를 둔다. 에이전트가 우회 prop을 추가하지 않는다. 재현 blueprint와 화면 근거로 issue → 카탈로그/renderer 수정 → 양성/음성/대비/회귀 검사 → 버전과 변경 로그 → lock 갱신을 따른다. 이전 버전 입력은 자동으로 새 규칙을 적용하지 않고 실패시킨다. 시스템은 미감의 영구 정답이 아니라 개정 가능한 계약이다.

## 규모·가용성·실패

초기 6테마 × 후보3, 4셸, 3타입, 3밀도, 3반경. 이 숫자는 디자인 품질이나 서로 다른 완성 화면 수가 아니다. 트리는 입력당 최대 100노드·깊이 6·JSON 128KiB. 정적 서버 하나로 실행하며 외부 API/LLM/런타임 패키지 의존은 없다. 동일 입력은 동일 출력. 오류 시 기존 유효 미리보기를 유지하고 내보내기를 막는다. 폰트는 시스템 폴백으로 오프라인 실행한다.

## 근거

`docs/sources.md`에서 커밋·원문 경로·검증 수준·라이선스를 관리한다. 동료 저장소의 AGPL 코드·토큰·레이아웃은 복사하지 않는다. 겨울 디자인시스템의 커밋된 파일을 주요 참조로 읽으며 진행 중 로컬 변경은 참고 정본에서 제외한다.

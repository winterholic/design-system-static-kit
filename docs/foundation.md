# 시각 기반 재설계 (2026-10-19)

직전 라운드(이중 제목, 상품 격자, 요금제·표·지표 위계)는 개별 결함을 고쳤다. 그 뒤에도 "배포 수준에 못 미친다"는 평가가 남아 부품 땜질을 멈추고 **시각 언어의 기반**을 다시 정했다. 이 문서는 진단, 결정, 이유, 반복 기록, 남은 약점을 적는다. 카탈로그(2.0.0)의 축 이름·값·금지 조합·규칙은 그대로이고, 축 값이 구현되는 방식(`src/styles/`, 렌더 일부, 토큰 중립색)이 바뀌었다.

## 1. 진단 방법

- **표본.** 배포본(https://design-system-static-kit.vercel.app) 대표 27페이지를 390/1280px로 촬영했다(랜딩·홍보 8종, 대시보드·관리·채팅·설정 7종, 커머스·요금 4종, 블로그·아티클·문서 3종, 인증·오류·상태 5종). 수정 중에는 랜딩류 9종(제품·피트니스·태양광·여행·강의·병원·후원·포트폴리오·사례)과 극단 사례 6종도 같이 찍었다. 기준 저장소 winterholic-design-system의 AIP(홈·문서·사례), notting, ttakkari 화면도 같은 폭으로 찍었다. stock-gosu 프리뷰는 `file://`로 열면 CSS가 빠져 비교에서 제외했다.
- **수치.** `.qa/metrics.mjs`가 페이지마다 제목 크기·굵기, 본문 크기, 섹션 간격, 상자(테두리 또는 그림자 + 모서리) 수, 중첩 상자 수를 측정한다. 아래 표는 그 결과다. 측정 도구와 원본 이미지는 `.qa/`(gitignore)에 있고, 요약 이미지는 이 Run의 산출물 폴더에 복사했다.
- **한계.** Linear·Stripe·Vercel 실제 사이트는 이 환경에서 촬영하지 않았다(네트워크 비교는 하지 않음). 기준은 사용자가 지정한 winterholic-design-system이다.

## 2. 왜 못생겼는가: 기반 요소별 진단

| # | 기반 요소 | 배포본(전) 수치 | 기준(AIP 등) | 판단 |
|---|---|---|---|---|
| 1 | **타이포 위계** | 랜딩 첫 h1이 24px 소제목, 히어로 h2가 44px(본문 대비 2.75배). 앱 화면 h1도 44px. 헤딩 굵기가 axis에 따라 500(article·blog)까지 내려가 본문과 구분이 약함 | 히어로 60~64px(3.75배), 섹션 제목 36~48px, 앱 h1 30px, 헤딩 700 | 랜딩은 제목이 작고 앱은 크다. 거꾸로다. 화면 종류별 제목 역할이 없었다 |
| 2 | **간격 리듬** | 모든 최상위 블록 간격이 28~56px 하나(`--kit-section`). 랜딩 섹션 사이 중앙값 28px, 섹션 안 머리말과 내용 간격도 같은 계열 | 섹션 상하 80~120px 밴드, 머리말→내용 40px 이상, 블록 사이 24px | 큰 묶음과 작은 묶음 간격이 같아 어디서 끊어 읽을지 알 수 없다 |
| 3 | **면 분할(밴드 부재)** | 모든 섹션이 컨테이너(1080px) 안에 갇혀 같은 바탕. 랜딩 1페이지에 면 색 구분 거의 없음 | 전폭 밴드가 canvas/soft로 번갈아 나오고 CTA가 색 면 | 페이지 스크롤이 한 덩어리로 보인다 |
| 4 | **상자 남용** | saas-landing: 상자 20개, 그 안의 상자 4개, 그림자 17개. 기능·인용·FAQ·요금제 전부 같은 흰 카드 | 상자는 요금제·폼·표에만. 기능은 맨 항목, 인용은 큰 글, FAQ는 헤어라인 | 위계가 전부 "카드"라 초점이 없다 |
| 5 | **시각 초점·이미지 자리** | 히어로 오른쪽은 막대 6개 장난감 그림. 상품 6개가 완전히 같은 그림(해+언덕) 6장. 히어로가 연한 상자 안에 갇힘 | 히어로가 페이지 폭 전체, 제품 화면 목업, 이미지마다 구도가 다름 | 화면이 "템플릿 껍데기"로 읽힌다 |
| 6 | **중립색** | 글자·보조·경계가 팔레트와 무관한 고정 청회색(#182029/#586476/#DDE2E7) | 중립색이 브랜드 색조를 약하게 띤다(notting의 종이색, AIP 웜 잉크) | 갈색·분홍 팔레트에서도 차갑고 회색이 도드라진다 |
| 7 | **컴포넌트 제목** | 폼·표·차트 카드 제목이 섹션 제목과 같은 h2 단계 크기라, h2를 키우면 카드 제목이 같이 커지는 구조 | heading-3(20px)로 고정 | 섹션 제목을 키우려면 먼저 분리해야 했다 |

### 상위 문제 (보고용)

1. 타이포 위계가 거꾸로다(랜딩 제목 작고 앱 제목 큼, 굵기 하한 없음).
2. 간격이 한 단계뿐이라 섹션 리듬이 없다(밴드 없음).
3. 모든 것이 같은 흰 카드다(상자 20개, 중첩 4개).
4. 히어로와 이미지 자리가 장난감 수준이다(같은 그림 반복, 막대 6개).
5. 중립색이 팔레트와 무관한 청회색이다.

## 3. 기준 저장소에서 가져온 것과 가져오지 않은 것

가져온 것은 값이 아니라 **규칙과 비율**이다. 이 저장소 AGENTS.md가 AGPL 동료 저장소(design-system-kit)의 코드·토큰은 복사하지 말라고 하는데, winterholic-design-system은 사용자 본인 저장소라 참조한다. 그래도 CSS 파일을 복사하지 않고 아래 규칙을 이 저장소의 축 구조에 맞게 다시 썼다.

| 가져온 규칙 | 출처 문서 | 여기서의 구현 |
|---|---|---|
| 텍스트 스타일 이름 고정과 역할(display·heading-1~3), 앱 h1 30px | `winterholic-base/docs/02-typography.md` §5 | `--kit-display`(히어로), `--kit-title`(콘텐츠 h1), `--kit-apptitle`(앱 h1), `--kit-h2`, `--kit-h3` |
| 굵기 600 이상, 800 이상은 뭉침 | 같은 문서 §3 | 제목 굵기 하한 600. 800은 `bold` 축 값에만 남김 |
| 제목 아래 설명은 한 단계 작고 옅게, 본문 한 줄 폭 제한 | 같은 문서 §5, §6 | 리드 18~20px 54~60ch, 문단 `text-wrap:pretty` |
| 전폭 밴드와 canvas/soft 교대, 컨테이너 안 정렬 | AIP `examples/home.html` 관찰 | 마케팅 페이지 유형의 최상위 섹션을 전폭 밴드로, 안쪽은 `--kit-bleed` 패딩으로 컨테이너에 정렬 |
| 상자는 경계가 필요한 곳에만 | `04-shape-elevation.md` 취지 | `--kit-open-*`: flat·outline·soft 깊이에서는 기능·인용을 상자 없이 |

가져오지 않은 것: **Pretendard 웹폰트.** 기준 저장소는 Pretendard를 쓰지만 이 저장소의 생성 페이지는 CSP가 `default-src 'none'`(외부 요청 금지)이고, 폰트를 `data:`로 박으면 페이지 3,380개가 각각 수 MB가 된다. 서체 스택은 시스템 폰트로 유지했다(iOS·macOS는 Apple SD Gothic Neo, Android는 Noto Sans CJK). 이 선택이 약점으로 남는다(§6).

## 4. 바꾼 기반 결정

### 타이포
| 항목 | 전 | 후 | 이유 |
|---|---|---|---|
| 히어로 제목 `--kit-display` | 없음(`title` 44px 공용) | tight 34~52, balanced 38~64, dramatic 46~96 | 히어로는 페이지에서 가장 큰 글자여야 한다(본문 대비 4배 안팎) |
| 콘텐츠 h1 `--kit-title` | 28~44px | balanced 32~48px | 기사·블로그 제목을 키우되 히어로보다는 작게 |
| 앱 h1 `--kit-apptitle` | 44px(콘텐츠와 동일) | balanced 26~30px | 앱 화면은 제목보다 데이터가 주인공. 제목+설명+오른쪽 액션을 한 줄로 |
| h2 | 24px | balanced 25~34px | 섹션 제목이 카드 제목과 구별되도록 |
| 굵기 axis | 500/650/800 | 600/700/800 | 500 제목이 본문(400)과 구분이 약했다(article·blog 측정) |
| 컴포넌트 제목 | h2 크기를 상속 | 부품 안 제목은 `--kit-h3`로 고정 | h2 단계를 키워도 폼·표 제목이 같이 커지지 않게 |
| 본문 보조 문단 | 14px | 카드·기능 설명 15px | 14px 설명이 18px 제목 아래서 너무 작았다 |
| 기사 본문 | 16px | 18px(`data-page=article`) | 긴 글 가독성 |

### 간격과 레이아웃
| 항목 | 전 | 후 | 이유 |
|---|---|---|---|
| `.kit-main` | 폭 제한 flex 열 | 3열 그리드(`full / content / full`), 컨테이너 밖까지 밴드 가능 | 전폭 배경과 컨테이너 정렬을 한 구조로 |
| 섹션 리듬 `--kit-band` | 없음 | compact 56 / comfortable 80 / spacious 104 (모바일 ×0.62) | 마케팅 페이지 섹션 상하 여백 |
| 밴드 교대 | 없음 | 랜딩·요금·포트폴리오·일반 페이지에서 짝수 섹션이 `soft` 면, 첫 섹션과 inverse는 그대로 | 면 분할로 스크롤 리듬 |
| 컨테이너 정렬 | 헤더·푸터가 24px 패딩 | 헤더·푸터도 `--kit-bleed`로 본문 열에 정렬 | 로고와 본문 왼쪽 선이 맞는다 |
| 앱 화면 바탕 | 흰색 | `soft`와 `canvas` 중간색(백드롭이 plain일 때) | 흰 카드가 경계선 없이 분리 |
| 폼 입력 폭 | 컨테이너 전체 | 단일 열 폼은 560px | 926px 입력칸은 읽기 어렵다 |
| 사이드바·스플릿·레일 열 | sticky 100vh만 칠함 | 열 전체를 그라디언트로 칠함 | 긴 페이지에서 열 아래 빈 바탕이 보이던 것 제거 |
| 랜딩의 `page-header` | 24px 소제목이 히어로 위에 | 접근성용으로만 남기고 시각적으로 숨김(h1 유지) | 히어로가 곧 제목 |

### 표면·색
| 항목 | 전 | 후 | 이유 |
|---|---|---|---|
| 기능·인용·FAQ | 모두 흰 카드(그림자) | flat·outline·soft 깊이에서는 상자 없음. FAQ는 헤어라인 목록. lifted·glow·hard는 상자 유지 | 깊이 axis가 성격 선택인 테마(brutalist, neon)는 상자가 정체성이다 |
| 히어로 | 연한 상자 안, 장난감 그림 | 전폭 밴드, 방사형 틴트, 제품 UI 목업 창 틀(chart·diagram 시각) | 시각 초점 |
| CTA | 상자 | 전폭 밴드(brand 톤은 색 면) | 페이지 끝 행동 유도 |
| 중립색 | 고정 청회색 | text·muted·border가 브랜드 시드 색조를 9~14% 섞음 | 갈색·분홍 팔레트에서 차가운 회색이 튀지 않게. 대비 하한은 그대로(`ensure`가 통과할 때까지 이동) |
| 이미지 자리 | 같은 그림 반복 | `photo`는 6개 구도 순환(해 위치·언덕 형태·색 교대), `chart`는 사이드바·지표·꺾은선·표 행이 있는 앱 목업 | 같은 그림 6장 제거 |

## 6. 남은 약점 (정직한 평가)

- **서체.** 시스템 폰트라 Windows·Android에서는 한글이 기준 저장소(Pretendard)만큼 단정하지 않다. CSP를 완화하지 않고 해결하려면 폰트 서브셋을 빌드 산출물에 싣는 설계(페이지가 아닌 공용 파일)가 필요하다. 미해결.
- **이미지 자리.** 6개 구도와 앱 목업까지는 갔지만 여전히 도형 그림이다. 실제 사진·일러스트가 있는 서비스 첫 화면 수준은 아니다.
- **랜딩 구조 한계.** 템플릿 데이터가 섹션 소개 문장(description)을 갖지 않아 섹션 머리말이 제목 한 줄이다. 2열 편집 레이아웃(왼쪽 라벨, 오른쪽 본문)은 부품 추가가 필요해 이번에 하지 않았다.
- **문서·블로그 페이지**는 간격은 좋아졌지만 위계가 가장 밋밋하다(목차, 코드 블록 스타일을 손대지 않았다).
- **밴드 교대는 규칙 기반.** 섹션 수·종류가 달라지면 짝수 섹션 면이 의도와 다르게 나올 수 있다(예: 2개 섹션뿐인 페이지).
- 그라디언트·틴트 중간색 위 글자 대비는 양 끝 토큰이 통과한 값이라는 근거만 있다(보간 구간 직접 측정 안 함, 확인 필요).
- 실기기 Safari/iOS·스크린리더는 미검증(Chromium만).

# 간격 규칙 (Spacing Contract)

> 이 문서는 `src/spacing.mjs`에서 생성됩니다(`npm run docs`). 손으로 고치지 않습니다. 값과 규칙은 모두 코드가 읽는 데이터이고, 문서는 그 사본입니다.

AI가 UI를 만들 때 자주 하는 간격 실수(제목-본문 거리가 부품마다 다르다, 라벨과 값이 멀다, 상자 안 글자가 가장자리에 붙는다, 6·10·14px 같은 임의 값, 중첩 상자의 여백이 겹친다)를 **기본 재료 단계에서 만들 수 없게** 한다. 사용자가 입력하는 Blueprint에는 간격 값이 없다. 간격은 (1) 밀도 축이 고르는 토큰 한 벌, (2) 그 토큰만 쓸 수 있는 CSS, (3) 생성된 계약 층, (4) 구조 검증기, (5) 렌더 실측으로 정해진다.

## 원칙

1. **거리는 관계다.** 가까울수록 한 묶음이다. 그래서 묶음 안 간격은 묶음 사이 간격보다 작아야 한다(tight < near ≤ item ≤ head < gap < section < band).
2. **같은 관계는 같은 값이다.** 부품이 달라도 제목→본문은 항상 `head`, 라벨→값은 항상 `tight`·`near`다.
3. **값은 고르는 것이다.** 4px 격자와 이름 붙은 토큰 밖의 값은 만들 수 없다.
4. **붙이는 것이 기본인 경우와 같은 규격을 따르는 경우를 나눈다.** 아래 표 S01(붙임)과 S02(같은 규격)가 그 구분이다.

## 두 가지 경우: 붙임 vs 같은 규격

| 경우 | 예 | 간격 | 이유 |
|---|---|---|---|
| **최대한 붙인다** (S01) | 속성 이름↔값, 지표 라벨↔숫자, 목록 제목↔부연, 가격↔평점, 카드 안 메타↔제목↔본문, 입력칸↔도움말 | tight 4px 또는 near 8px | 한 문장처럼 읽혀야 한다. 멀어지면 라벨이 값에서 떨어져 두 항목으로 읽힌다. |
| **같은 규격을 따른다** (S02, S08) | 부품 제목↔본문(목록·표·FAQ·단계·타임라인·팀·갤러리·폼 등), 섹션 머리말↔내용 | head(12·16·20), 섹션 머리말은 gap | 제목마다 거리가 다르면 화면이 어수선해 보인다. 부품이 달라도 같은 값이다. |
| 항목 사이 | 목록 줄, 폼 필드 사이, 칩 | item·sub | 묶음 안의 항목이므로 묶음 사이(gap)보다 작다. |
| 큰 덩어리 사이 | 부품↔부품, 섹션↔섹션 | gap · section | 묶음 안보다 항상 크다. |

## 규칙

### S01 라벨 ↔ 값 (붙임)

붙여 읽는 한 쌍은 가장 가깝게 둔다: 속성 이름↔값, 목록 제목↔부연, 가격↔평점, 입력칸↔도움말은 tight(4px), 지표 라벨↔숫자·카드 제목↔본문은 near(8px)를 넘지 않는다.

- 쓰는 단계: tight 4 · near 8
- 적용 부품: 속성 목록, 지표, 목록 항목, 타임라인, 카드 본문, 리뷰, 메뉴, 입력칸
- 강제 방법: CSS 린트 + 렌더 측정 PAIR_GAP

### S02 부품 제목 ↔ 본문 (같은 규격)

부품의 제목(h2~h4)은 어떤 부품이든 같은 간격(head)으로 본문에 붙는다. 제목 바로 뒤에 한 줄 설명이 오면 제목↔설명은 near, 설명↔본문은 head. 부품마다 임의의 값(4·6·12·16·24)을 쓰지 않는다.

- 쓰는 단계: head 12·16·20
- 적용 부품: 목록·표·차트·폼·요약·속성·링크·달력·FAQ·단계·타임라인·팀·갤러리·릴
- 강제 방법: 생성된 계약 층(contractCSS) + 렌더 측정 HEAD_GAP

### S03 묶음 안 < 묶음 사이 (근접)

한 묶음 안의 간격은 그 묶음과 이웃 묶음 사이의 간격보다 크지 않다. 안쪽이 더 넓으면 글이 어느 쪽에 속하는지 읽히지 않는다.

- 쓰는 단계: near < item < gap
- 적용 부품: 모든 쌓임(세로 배치)
- 강제 방법: 렌더 측정 PROXIMITY

### S04 표면 상자의 안쪽 여백

배경·테두리가 있는 상자에서 글자는 가장자리에서 12px(높이 80px 미만이면 8px) 이상 떨어진다. 좌우 안쪽 여백은 같고, 위아래는 8px 넘게 다르지 않다.

- 쓰는 단계: inset·insetS
- 적용 부품: 카드·폼·표·차트·알림·요약·구매 박스·칸반
- 강제 방법: 렌더 측정 EDGE · PAD_ASYM

### S05 중첩 표면은 안쪽이 작다

표면 안의 표면은 바깥보다 작은 여백(insetS)을 쓴다. 색을 입힌 섹션 안에 색을 입힌 섹션을 넣지 않고(SURFACE_NEST), 섹션은 두 단계까지만 중첩한다(SECTION_DEPTH).

- 쓰는 단계: inset ≥ insetS
- 적용 부품: 섹션·카드·칸반 카드·말풍선
- 강제 방법: 검증기 SURFACE_NEST · SECTION_DEPTH

### S06 컨트롤 안쪽 여백

글자가 있는 버튼·입력의 가로 안쪽 여백은 세로의 1.5배 이상이다. 높이는 밀도 토큰(control 40·44·48)이 정한다.

- 쓰는 단계: 세로 8 · 가로 16~24
- 적용 부품: 버튼·입력·선택·텍스트 영역
- 강제 방법: CSS 린트 + 렌더 측정 CTRL_PAD

### S07 4px 격자

모든 margin·padding·gap은 토큰이거나 4의 배수(1·2px 헤어라인 예외)다. 6·10·14·18·22px 같은 중간 값과 .4·.7·.9·1.2 같은 임의 배수는 쓰지 못한다. 유동(clamp) 값은 히어로·CTA·빈 화면·로고 줄 등 지정한 선택자에서만 쓴다.

- 쓰는 단계: 4의 배수 + 1·2px
- 적용 부품: 모든 CSS
- 강제 방법: CSS 린트(lintSpacing) + 렌더 측정 OFF_SCALE

### S08 섹션 머리말

눈썹글↔제목↔설명은 near(8px)로 묶고, 머리말↔내용은 gap으로 한 번만 띄운다. 머리말에 별도 아래 여백을 더 얹지 않는다.

- 쓰는 단계: near · gap
- 적용 부품: 섹션 머리말
- 강제 방법: 렌더 측정 HEAD_GAP

### S09 묶음 사이의 리듬

한 부품 안의 블록 사이는 gap, 화면의 큰 덩어리 사이는 section, 마케팅 전폭 띠의 위아래는 band다. 이 순서는 밀도 3종 모두에서 gap < section < band로 고정이다.

- 쓰는 단계: gap < section < band
- 적용 부품: 페이지·섹션·띠
- 강제 방법: 단위 시험(토큰 순서) + 렌더 측정 PROXIMITY

### S10 고아 제목 금지

본문이 없는 제목(부품의 첫 자식이자 유일한 자식)을 만들지 않는다.

- 쓰는 단계: —
- 적용 부품: 모든 부품
- 강제 방법: 렌더 측정 HEAD_ORPHAN

## 유동 값의 예외 (S07)

히어로·CTA 띠·빈 화면·로고 줄 등은 화면 폭에 따라 연속으로 변하는 `clamp()`를 쓴다. 허용 선택자: `.kit-section-head`, `.kit-hero`, `.kit-cta`, `.kit-empty`, `.kit-logos`, `.kit-features`, `.kit-quote`, `[data-page=auth]`, `[data-page=error]`, `[data-shell=editorial]`. 이 밖에서 clamp를 쓰면 린트가 실패한다.

# 규칙 개정과 소비 프로젝트 적용

1. 재현: 어느 Blueprint·카탈로그 버전·상태·뷰포트에서 문제가 있는지 기록한다. 기존 규칙의 의도와 실제 결과를 연결한다.
2. 판단: 기존 노드 variant로 해결되는지 확인한다. 표현의 의미가 새로우면 노드를, 시각 변형이면 variant를, 제품 고유 도메인이면 버전 고정 어댑터를 설계한다.
3. 수정: `src/catalog.mjs`와 필요한 renderer만 바꾸고, 정상 fixture/실패 fixture를 먼저 추가한다. 임시 `style`, `className`, `html` prop은 만들지 않는다.
4. 검증: `npm run verify`, browser regression, 실제 색 쌍, 모바일·키보드·긴 텍스트. 판정한 범위와 미검증을 기록한다.
5. 배포: 카탈로그 버전과 CHANGELOG를 함께 올린다. 이전 blueprint는 자동 변환하지 않는다. 명시적인 catalogVersion 변경과 재검증으로 옮긴다.

## 기존 winterholic-design-system과의 관계

이 kit는 새 디자인시스템을 정해진 문법으로 파생하기 위한 독립 조립기다. 기존 앱의 AIP·따까리·stock-gosu 브랜드 정본을 자동 대체하지 않는다. 해당 시스템의 컴포넌트·도메인 토큰을 수입하려면 source commit → 역할 매핑 → 허용 노드 → 대비/상태 검증의 어댑터를 별도로 작성한다. 원본 디자인시스템의 소유 결정이 kit의 일반 기본값보다 우선한다.

## 강제성 운영

CI 필수 검사, 보호 브랜치, CODEOWNERS, 사용 카탈로그 버전 pinning을 소비 저장소에서 설정한다. 이 저장소는 코드와 CI를 제공하며 GitHub 관리 정책을 강제로 설정하지 않는다. 규칙이 틀렸을 때는 규칙의 근거와 반례를 고치는 것이 정규 경로다. 실패 결과를 프롬프트로 덮거나 생성물을 손수 고치는 것은 다음 생성에서 사라진다.

## 후속 확장

React/Vue 어댑터, 차트·다이얼로그·탭 등의 상호작용 부품, 기존 제품별 브랜드 수입기, 허용되는 다중 페이지 링크를 추가할 수 있다. 현재 제공 범위인 13종 정적 노드와 입력 확인 데모를 운영 서비스 전체 기능으로 오인하지 않는다.

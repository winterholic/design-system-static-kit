# ADR 0004: 타입 역할, 배치 원시 요소, 컨셉, 품질 게이트

- 상태: 채택(6차 품질 라운드, 2026-10-21)
- 앞선 결정: ADR 0001(닫힌 카탈로그·컴파일러), ADR 0003(간격 계약)

## 배경

5차까지의 시험(간격 실측, 글줄 실측, 구조 검증)은 모두 통과했는데도 사용자가 `/combos/`에서 본 조합 중 못생긴 것이 많았다. 전수 진단(`docs/diagnosis-round6.md`)이 이유를 보여 줬다. 기존 시험은 **부분의 일관성**(제목↔본문 간격, 줄바꿈, 가로 넘침)을 재고, **구성의 품질**(칸이 비었는가, 큰 글자가 좁은 칸에 접히는가, 격자 마지막 줄에 한 칸만 남는가, 제목 위계가 뒤집혔는가)은 재지 않았다. 원인은 네 갈래였다.

1. 부품이 자기 크기·열 수·칸 비율을 직접 정했다(font-size 58종, 격자 열 수 고정, 벤토 첫 칸 항상 2×2).
2. 구성 변형이 서로의 조건을 모른 채 곱해졌다(앱·문서 화면의 가운데 정렬 머리말이 조합의 절반, 서로 다른 종류의 벤토를 같은 높이 격자에 넣기, 3개를 2열로).
3. 서체가 8종 스택 이름 하나였고 비율·자간·행간은 모든 서체가 같았다.
4. 템플릿이 테마 하나에 묶여(1테마-1템플릿) 못생긴 하나가 그 주제 전체의 인상이 됐다.

## 결정

**크기는 역할이다.** 부품 CSS는 `font-size`로 `var(--kit-t-<역할>)`만 쓴다(29개 역할). 역할의 값은 서체 프리셋(`src/typography.mjs`, 18종)의 비율·본문 크기·`scale` 축으로 계산하고, 좁은 화면의 최솟값도 위계 순서를 지키도록 묶는다. 24px을 넘는 역할은 허용된 자리(선택자)에서만 쓸 수 있다. `lintType`이 스타일시트 전체를 검사한다.

**격자는 흐름이다.** 같은 크기 항목의 격자는 `data-flow`·`data-n`·`data-cap` 표지만 달고, 열 수는 컨테이너 폭과 항목 수가 정한 표(`src/layout.mjs` `bestCols`)에서 CSS가 생성한다. 마지막 줄에 한 칸만 남는 열 수는 만들어지지 않는다. 벤토는 시각 요소가 있는 칸만 2×2로 키운다(`bentoPlan`). `lintLayout`이 흐름 밖의 반복 격자 선언을 막는다.

**구성 변형은 적용 조건을 가진다.** 슬롯·옵션은 페이지 유형(`pages`)과 내용 조건(`when`)을 모두 만족할 때만 나타난다. 항목 수와 맞지 않는 열 수, 섞인 벤토의 균등 격자, 앱·문서·데이터 화면의 가운데 정렬 머리말은 만들지 않는다.

**컨셉이 템플릿과 시각 언어를 묶는다**(`src/catalog/concepts.mjs`). 한 컨셉은 템플릿 여러 개와 look(테마+서체+선택적 테마 변형) 여러 벌을 가진다. 서체는 테마와 독립이며 테마마다 서체 변형(`type-<프리셋>`)을 더 가진다.

**품질 게이트.** `scripts/design-qa/diagnose.mjs`가 전 조합을 1440·390에서 세 프로브로 재고 A·B·C 등급을 매긴다(`diagnose-meta.mjs`). C 등급은 `src/combo-grades.mjs`에 기록되어 갤러리에서 '실험'으로 표시되고 기본으로 숨겨진다. CI(`e2e/quality.spec.mjs`)는 고정 시드 표본을 같은 프로브로 다시 재고, 프로브가 결함을 실제로 잡는지 음성 대조로 확인한다. 등급 파일이 현재 카탈로그와 어긋나면 시험이 실패한다(`tests/grades.test.mjs`).

## 선택하지 않은 것

- **웹폰트 포함.** 생성 페이지는 `default-src 'none'` CSP의 자기완결 문서다. 한글 서체는 부분 집합도 수백 KB라 페이지마다 넣기 무겁고 갤러리가 수십 쪽을 동시에 연다. 시스템 서체만으로 비율·굵기·자간·행간에서 목소리를 낸다. 후보와 라이선스(OFL)는 `docs/typography.md`에 기록했다.
- **조합 수를 인위적으로 늘리기.** 새 구성(섹션 머리말 가운데, 질문 좌우 분할, 단계 카드)은 마케팅 페이지에서만 나타나며, 진단으로 걸러진 C 등급은 실험으로 내린다.
- **등급을 미감의 보증으로 쓰기.** 등급은 측정 가능한 결함의 유무다. 전수를 사람이 보지는 않았다.

## 결과와 위험

- 조합 수는 4,102에서 달라졌다(늘린 것과 줄인 것의 차이는 `docs/round6-quality.md`).
- 등급은 macOS 폰트로 얻었다. Linux 폰트에서 달라질 수 있어 CI 표본으로 다시 잰다.
- 컨테이너 쿼리(`@container`)와 `:has()`에 기댄다. Safari 16 미만과 구형 브라우저에서는 기존 CSS의 대체 열 수로 내려간다(실기기 확인은 못 했다).
